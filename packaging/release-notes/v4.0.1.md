## What's new in 4.0.1

One change, and it is a step back on purpose.

### "Keep the HUD sharp" is off again unless you switch it on

4.0 switched it on for everyone. It did what it was made for (a HUD that stands still in front of a
moving world kept its real pixels in generated frames), and it also added artifacts around the edges of
moving things, seen with NVIDIA's frame generation on an RTX 5090. Its thresholds had been set on drawn
test pictures; a real game has many more pixels that happen to be the same in two frames.

- With the switch off, which is now the default, generated frames are exactly what they were before 4.0:
  the graph has no pass for the rule at all.
- If you switched it on or off yourself, your choice is kept. It is still there as an experiment:
  *Quick setup → Keep the HUD sharp*.
- Live HUD Lock, game presets and Automatic HUD detection are not changed.
- Everything else in 4.0 stays as it is, the steadier 60 → 30 rhythm included.

### What was tested where

The change is the default of one switch, checked by the unit tests and the interface tests in CI. That
generated frames are back to what they were follows from the code (with the switch off no pass is created);
it has not been looked at on a card again.
